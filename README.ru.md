# Stabilizer

[English](README.md) · [Español](README.es.md) · [Лицензия](LICENSE)

Нативный монитор памяти и управление приоритетами `systemd-oomd`.

**Первая версия: Ubuntu 26.04, Linux 7.0 и новее, systemd 259+, cgroups v2.**
Архитектура первого проверяемого пакета: amd64. Другие Debian-системы пока не поддерживаются.

## Возможности версии 0.1

- GTK4 / libadwaita GUI, Rust, без WebView и Electron.
- Английский, испанский и русский: переключатель в шапке окна, сохранение выбора, переводы меню трея и сообщений.
- RAM, доступная память, swap, PSI; обновление раз в 2 секунды.
- Память целой группы процессов через cgroups, а не сумма RSS с двойным учётом общих страниц.
- Приоритеты: защищённое (`omit`), высокое (`avoid`), обычное (`none`).
- Необязательный мягкий лимит `MemoryHigh`. Он вызывает reclaim/throttling, а не устанавливает жёсткую границу.
- Постоянные правила; повторное применение к новому экземпляру группы после перезапуска приложения.
- Проверка параметров systemd, фактических атрибутов cgroup и условий, при которых oomd учитывает защиту.
- Кнопка защиты D-Bus и GNOME Shell, список правил и история изменений.
- Удаление правила восстанавливает исходные параметры работающего экземпляра, если их не изменил другой инструмент.
- Значок в трее показывает RAM, swap, давление памяти и защиту по клику. Агент работает при закрытом GUI. `.deb` добавляет пользовательскую службу и D-Bus activation.
- Неподдерживаемая платформа: только просмотр, операции изменения запрещены также на стороне агента.

## Границы защиты

Защита относится **только к systemd-oomd**. Она не запрещает ручной `kill`, остановку сессии, падение приложения или OOM killer ядра. Stabilizer не завершает приложения самостоятельно.

`omit`/`avoid` не применяются рекурсивно. Версия 0.1 отказывается подтверждать защиту групп с вложенными cgroups и групп под родителем `memory.oom.group=1`. Системные правила oomd, применяемые к root-owned предкам, могут игнорировать пользовательские предпочтения. В таком случае интерфейс показывает, что действие защиты не подтверждено.

Приоритет `avoid` означает «выбирать после остальных подходящих кандидатов», а не гарантированный порядок завершения. `MemoryHigh` может создавать давление на память; поэтому его нельзя установить для защищённого приложения.

Таблица показывает процессы текущего пользователя внутри его systemd user manager. Системные службы, контейнеры Docker и процессы других пользователей не включаются в список. Полная память системы отображается отдельно. GNOME Shell может содержать дочерние приложения; политика такой строки относится ко всей группе.

Идентификатор для правила определяется по имени systemd unit без PID/UUID запуска. Разные способы запуска одной программы могут создавать разные идентификаторы. Такие строки нужно настроить отдельно. Службы идентифицируются полным именем unit.

## Сборка и запуск из исходников

Требуются Rust 1.92+, `pkg-config`, `libgtk-4-dev`, `libadwaita-1-dev`, GCC и штатная пользовательская D-Bus сессия.

```sh
cargo build --locked -j 2
cargo run --locked --bin stabilizer
```

GUI запускает соседний `stabilizer-agent` в отдельной службе `stabilizer-agent-dev.service`, если D-Bus activation ещё не установлена. Агент работает в собственной пользовательской службе с защитой от oomd и автоматическим перезапуском после аварии. Он использует только права текущего пользователя. Никаких sudo или изменений защиты GNOME при первом открытии нет.

```sh
cargo run --no-default-features --bin stabilizer-agent -- --check
cargo run --no-default-features --bin stabilizer-agent -- --once
```

`--once` читает статистику и выдаёт JSON; системные настройки не изменяются.
`stabilizer --demo` показывает демонстрацию с отключёнными действиями.

## Пакет

```sh
./scripts/build-deb.sh
sudo apt install ./dist/stabilizer_0.1.0_amd64.deb
```

Пакет ограничивает установку Ubuntu 26.04 / Linux 7+. После установки Stabilizer доступен в меню приложений. Агент запускается при следующем входе; открытие GUI может запустить его сразу через D-Bus. Текущие процессы и правила oomd пакет автоматически не меняет.

Состояние сохраняется в `${XDG_STATE_HOME:-$HOME/.local/state}/stabilizer/state.json`, права файла 0600. Запись атомарная с fsync. Повреждённое состояние не перезаписывается. Запуск агента от root запрещён.

Перед удалением пакета удалите правила во вкладке «Правила», если требуется сразу отменить их в работающих приложениях. Остановка агента прекращает повторное применение; уже выставленные runtime-параметры systemd могут сохраняться до завершения группы. Файл состояния при удалении пакета остаётся в пользовательской папке.

## Проверки

```sh
cargo test --locked --no-default-features
cargo clippy --locked --all-targets -- -D warnings
python3 scripts/live-smoke.py --release
python3 scripts/tray-smoke.py
python3 scripts/language-smoke.py
```

Live smoke создаёт только временную тестовую пользовательскую службу. Проверяет применение приоритетов, мягкого лимита, повторный запуск, обратимость и отсутствие изменения D-Bus/GNOME. Применение к рабочим приложениям выполняется только через выбранные пользователем правила.

## Устройство

```text
GTK4 GUI → D-Bus API → пользовательский агент → systemd user manager
                                ↓                     ↓
                         /proc + cgroups        omit / avoid / MemoryHigh
                                ↓
                        атомарное состояние
```

Сбор статистики и запись файлов выполняются вне GUI и вне асинхронного цикла агента. GUI обращается к D-Bus в отдельном worker thread. Агент сериализует операции изменения, хранит исходные значения до применения и проверяет InvocationID, чтобы не отменить настройки другого экземпляра процесса.

## Следующие версии

Защита от OOM killer ядра через узкий привилегированный помощник; точные правила порядка завершения; обработка вложенных cgroups; отслеживание активности окон GNOME Wayland; освобождение памяти по неактивности. В версии 0.1 эти функции не заявлены.

## Самозащита и лицензия

Самозащита агента: `ManagedOOMPreference=omit` и `Restart=always` в его собственной пользовательской службе. После аварийного завершения агент и трей восстанавливаются. Владелец системы может штатно отключить службу командой `systemctl --user stop stabilizer-agent.service`; это не вызывает автоматический перезапуск. Для запуска из исходников имя службы — `stabilizer-agent-dev.service`. Это защита от oomd и аварий, не запрет администратору управлять системой.

Личное использование, внутреннее использование в бизнесе, изменения и бесплатное распространение разрешены. Настоящие услуги поддержки/установки отдельно от продажи приложения разрешены.
